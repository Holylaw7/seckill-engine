# Codex 代码审查提示词

请作为高级 Java 架构师，对当前 Seckill-Engine 代码进行 Code Review。

## 审查范围

先阅读相关模块、设计文档、测试代码和 Git 状态。不要直接修改代码。

## 1. 高并发安全

检查：

- 是否存在超卖风险。
- 是否存在重复下单或重复扣减。
- 是否存在线程安全问题。
- Redis Lua 脚本的原子性、参数校验和失败回滚是否正确。
- 库存预扣与订单创建之间是否存在不一致窗口。
- 限流、快速失败和熔断是否会放大流量。

## 2. 分布式问题

检查：

- 分布式锁的加锁、解锁、续期和异常释放是否可靠。
- RocketMQ 事务消息是否可能丢失。
- 消息重试、死信和重复消费是否有处理。
- 消费者是否具备幂等性。
- 服务重启、网络分区和超时后的行为是否明确。

## 3. 数据一致性

检查 Redis、RocketMQ、MySQL 三者之间是否最终一致：

- Redis 预扣流水是否可追踪。
- MySQL 是否是最终库存事实源。
- 订单、库存、支付状态是否存在非法跳转。
- 回补、取消、超时和退款是否幂等。
- 对账、修复和人工补偿是否有审计留痕。

## 4. 性能问题

分析：

- CPU 使用率和线程池配置。
- 堆内存、GC 和对象分配。
- 数据库连接池、锁等待、慢 SQL 和死锁。
- Redis QPS、热点 Key 和 Lua 执行耗时。
- RocketMQ 生产吞吐、消费吞吐和 backlog。
- Gateway 限流、路由和鉴权开销。

## 5. 安全问题

检查：

- 接口鉴权和越权访问。
- 参数校验和边界值。
- 重放攻击、刷单和恶意并发。
- JWT、回调验签和内部接口签名。
- 敏感信息日志泄露。
- 管理接口权限和操作审计。

## 输出格式

按严重程度输出：

1. 严重问题：阻断发布或可能造成资损。
2. 高风险问题：可能造成数据错误、消息丢失或明显性能退化。
3. 中低风险问题：工程质量、可维护性或可观测性问题。
4. 优化建议。
5. 修改方案。
6. 测试补充建议。

每个问题应包含文件位置、问题证据、影响、修复建议和验证方式。

不要直接修改代码，等待用户确认后再实施修复。
