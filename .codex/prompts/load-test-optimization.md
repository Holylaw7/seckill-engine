# Codex 压测与性能优化提示词

现在进入 Seckill-Engine 性能测试阶段。

## 目标

验证系统是否满足：

- 核心秒杀接口 `10000+ QPS`。
- 高并发下零超卖。
- 零重复订单。
- RocketMQ 消息最终收敛。
- Redis、MySQL、服务实例资源可控。

## 首先生成

1. JMeter 测试方案。
2. 压测脚本。
3. 测试数据。
4. 环境拓扑与容量假设。
5. 测试前置条件和清理方案。

## 测试指标

至少采集：

- QPS。
- TPS。
- 平均 RT。
- P95。
- P99。
- 错误率。
- CPU。
- Memory。
- GC。
- Redis QPS、命中率和慢命令。
- MySQL QPS、连接数、锁等待、慢 SQL 和死锁。
- RocketMQ 生产吞吐、消费吞吐和 backlog。
- 成功订单数、库存剩余量和重复消费数。

## 执行流程

发现瓶颈后严格按照以下顺序：

```text
定位问题
→ 保存测试证据
→ 分析根因
→ 提出优化方案
→ 等待确认
→ 修改代码或配置
→ 测试验证
→ 对比基线
→ Git提交
```

## 正确性门禁

压测通过不能只看吞吐量，还必须验证：

- 成功订单数不超过库存。
- 库存不出现负数。
- 同一用户不会生成重复有效订单。
- 重复消息只产生一次业务效果。
- 取消、超时、退款回补只执行一次。
- Redis 与 MySQL 最终一致。
- MQ backlog 在规定时间内归零。

## 输出内容

最终输出：

1. 测试环境。
2. 测试场景。
3. 测试数据。
4. QPS、TPS、平均 RT、P95、P99。
5. CPU、Memory、GC。
6. Redis、MySQL、RocketMQ 指标。
7. 瓶颈定位。
8. 优化前后对比。
9. 正确性验证结果。
10. 剩余风险和容量结论。
11. commit id。
