| 项目 | 内容 |
| --- | --- |

## 1. 设计目标

明确每个写操作的事务范围，杜绝“跨资源大事务”的误设计：Redis、RocketMQ、MySQL 各自独立事务，跨资源一致性由**消息 + 幂等 + 对账补偿**保证，而不是靠分布式事务。

## 2. 事务边界总览

| 环节 | 事务类型 | 事务范围 | 明确不包含 |
| --- | --- | --- | --- |
| Redis Lua 预扣 | Redis Script 原子事务 | 库存检查、用户检查、库存扣减、购买标记 | **不包含 MySQL 事务** |
| RocketMQ Producer 本地事务 | MySQL 本地事务 | 写入 `seckill_pre_deduct`（状态 INIT→SUCCESS/FAIL） | 不包含 Redis 扣减（已完成）、不包含 MQ 提交（半消息已发送） |
| Order Consumer 事务 | MySQL 本地事务 | 创建订单、写订单幂等记录、更新消费状态（订单置 WAIT_PAY） | 不包含其他服务数据库；**不直连 seckill 库** |

## 3. Redis Lua 扣减事务

- 事务范围：单脚本内所有命令由 Redis 单线程模型原子执行，等价于原子事务；
- 脚本内部先校验后变更（库存足够、未重复购买），不产生部分变更，无需回滚设计；
- 与 MySQL **无任何事务关联**：MySQL 后续失败不触发 Redis 回滚，而是通过补偿（库存回补流水）收敛；
- 失败语义：返回 `SUCCESS / STOCK_EMPTY / REPEAT_BUY / NOT_READY`，失败不产生 MQ 消息。

## 4. RocketMQ Producer 本地事务

- 事务范围：仅 `seckill_pre_deduct` 一条记录的写入（半消息发送后执行）；
- 状态冻结：

| 状态 | 含义 | Broker 映射 |
| --- | --- | --- |
| `INIT` | 半消息已发送，本地事务进行中/回查未知 | UNKNOWN |
| `SUCCESS` | 本地事务提交成功 | COMMITTED |
| `FAIL` | 本地事务失败 | ROLLBACK |

- 本地事务失败（FAIL）：**必须补偿回补 Redis 库存**（INCRBY + 回补流水），随后 Broker Rollback 丢弃消息；
- 边界：本地事务不包含订单落库（消费端负责）、不包含 Redis（已扣减）。

## 5. Order Consumer 事务

- 事务范围（同一 MySQL 本地事务，全部在 order 服务库内）：
  1. 创建订单（INSERT `seckill_order`）；
  2. 写订单幂等记录（INSERT `idempotent`，biz_type=ORDER_CREATE）；
  3. 更新消费状态（订单状态置为 WAIT_PAY）。
- **数据库事务提交成功后才返回 ACK（CONSUME_SUCCESS）**；事务失败返回 RECONSUME_LATER 进入重试，不提前确认；
- 幂等表唯一索引冲突视为已消费，直接返回成功；
- `seckill_pre_deduct` 属于 seckill 库：order-service **禁止直连**，事务提交后经内部接口通知 seckill-service 回填确认（order_id、deduct_status=CONFIRMED），失败由对账任务兜底。

## 6. 一致性保障总结

| 跨资源点 | 保障机制 |
| --- | --- |
| Redis 扣减 ↔ MQ 消息 | 事务消息（半消息 + 本地事务 + 回查），失败补偿回补 |
| MQ 消息 ↔ 订单落库 | 消费幂等 + 唯一约束，事务成功才 ACK |
| 订单落库 ↔ 库存确认 | 内部接口通知 + 对账兜底 |
| 最终收敛 | 对账任务（重投/回补/修复）+ 人工补偿 |
